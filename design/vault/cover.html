Six rules
1One sheet360 wide in every state, popover chrome, hanging from the key button. A state changes what is inside, never the frame.
2Open on the pageThe site's logins first, the first one chosen, the caret in search. Enter fills. The whole vault is a search or an arrow away.
3One primaryCyan for the focused field and one action per sheet: Fill, Unlock, Save. No filled button on a row.
4Shapes before wordsA fingerprint for a passkey, a clock for a code, a ring for its time, a diamond when sync fails. Plates in enamel name items.
5The record is rowsSettings' groups: label and value, tools on the right — copy, reveal, open. Edit turns them into fields in place.
6Housekeeping out of the waySync, account and Log out live in ··· and a one-line foot. Escape or a click on the page closes it.

For you to decide
Fill a login with a code: copy the code too? Bitwarden puts the one-time code on the clipboard after it fills, so the next page's code field is a paste away.
Enter on a site row fills; a click does too? Proposed: a click on a row of this site fills it, its › opens it. In the whole vault a click opens.
A key to open the panel. Today it opens only from the key button (and by itself when a site asks for a passkey).
Enamel plates or site icons? Plates are Sola's way of naming things and need no network; favicons are what Bitwarden shows and are recognisable at a glance.
